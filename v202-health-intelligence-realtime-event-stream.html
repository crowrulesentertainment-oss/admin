Event Classes

Health

Service status changes and health observations.

Incident

Detected, acknowledged, recovering, and resolved lifecycle events.

Recovery

Action, run, retry, scheduler, and execution events.

Notification

Queue, delivery, retry, failure, and routing events.

Intelligence

Detected signals, explanations, and operator review state.

Audit

Traceable lifecycle records across operational domains.

Stream Controls

Service Filter

Limit events to one CrowRules service.

Event Filter

Show health, incident, recovery, notification, intelligence, or audit events.

Time Window

Use bounded recent windows rather than unbounded streams.

Pause / Resume

Allow operators to inspect an event without losing context.

Event Contract

Recommended fields: event_id, event_type, service_key, source_table, source_id, occurred_at, severity, message, metadata.

Ordering: use server timestamps and stable event IDs; do not rely on browser clock ordering.

Deduplication: repeated deliveries should not create repeated visible events.

Security & Reliability

REAL-TIME READY • SERVER-AUTHORIZED
V202 defines the event-stream surface without exposing service-role credentials. Protected operational data remains behind authorization. The stream must tolerate reconnects, duplicate deliveries, stale subscriptions, and missing events without claiming that a service is healthy.

Platform State

No new Edge Function is deployed in V202. The existing project function-capacity limit remains respected. Real-time delivery should be connected through an authorized server-side or properly RLS-protected channel when the underlying implementation is enabled.
