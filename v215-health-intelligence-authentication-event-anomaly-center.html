Authentication Event Domains

SIGN-IN

Track successful and unsuccessful authentication events using minimal, non-secret metadata.

SESSION

Correlate session creation, refresh, expiry, logout, and revocation events.

RECOVERY

Connect password-recovery and verification events to the authentication timeline.

IDENTITY PROVIDER

Track provider-related authentication events without retaining raw OAuth credentials.

VERIFICATION

Review email or other approved verification events and their expected lifecycle.

AUTHORIZATION HANDOFF

Distinguish identity authentication from subsequent authorization decisions.

FAILURE PATTERNS

Identify changes in event volume, failure concentration, timing, or sequence without assuming malicious intent.

CHANGE CONTEXT

Compare authentication anomalies with documented configuration, deployment, or dependency changes.

Anomaly States

OBSERVED

A measurable event or pattern differs from the selected baseline.

CORRELATED

Related events or context have been identified without asserting causation.

REVIEWED

A human has assessed the evidence and documented the interpretation.

CLOSED

The investigation has a documented disposition and supporting evidence.

Confidence States

VERIFIED

Direct authoritative evidence supports the event or pattern.

SUPPORTED

Multiple relevant evidence sources support the observation.

PROPOSED

A possible anomaly requires validation.

UNKNOWN

Evidence is insufficient for a reliable conclusion.

Safe Telemetry Model

EVENT Record event type, outcome, timestamp, service, and safe correlation identifiers.

BASELINE Compare against an explicitly defined time window or expected sequence.

CONTEXT Link identity, session, recovery, OAuth, configuration, dependency, and incident evidence where supported.

MINIMIZE Avoid passwords, raw access tokens, refresh tokens, verification codes, authorization codes, and unnecessary personal data.

REVIEW Require human interpretation before treating an anomaly as a security finding.

Anomaly Record Contract

Recommended fields: anomaly_id, service_key, event_type, event_outcome, baseline_window, observed_window, observed_value, baseline_value, delta, sample_size, evidence_ids, detected_at, confidence_state, related_identity_audit_id, related_session_audit_id, related_recovery_audit_id, related_oauth_audit_id, related_incident_id, reviewed_by, reviewed_at, created_at, metadata.

Critical Guardrails

ANOMALY ≠ ATTACK
A statistical or behavioral difference does not by itself establish malicious activity, unauthorized access, or compromise. Investigation requires evidence and context.
CORRELATION ≠ CAUSATION
Two authentication events occurring near the same time as a configuration or deployment change do not establish that one caused the other.

Safety & Platform State

V215 is an analysis and audit surface. It does not block sign-ins, revoke sessions, lock accounts, change authentication settings, collect credentials, trigger remediation, send notifications, or delete records. No service-role credentials are exposed and no new Edge Function is deployed; the current project function-capacity limit remains respected.
