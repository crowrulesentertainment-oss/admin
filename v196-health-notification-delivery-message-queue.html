Queue Controls

Idempotency: each delivery item should have a stable dedupe/idempotency key.

Attempts: retries must be bounded; failed work must not loop indefinitely.

Backoff: retry timing should respect configured cooldowns and avoid notification storms.

Claiming: only trusted server-side workers may transition queued work into processing.

Audit: queue creation, attempts, delivery results, and cancellation should be traceable.

Recommended Queue Record

id · incident_id · service_key · template_key · channel · dedupe_key · status · attempt · available_at · claimed_at · sent_at · last_error · metadata
