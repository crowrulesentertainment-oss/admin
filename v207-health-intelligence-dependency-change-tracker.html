Change Stream

ARCHITECTUREBASELINEExisting service dependency relationship recorded for future comparison.—
CONFIGURATIONDETECTEDConfiguration changes can be correlated with a dependency edge only when evidence identifies the affected component.—
INTEGRATIONREVIEWNew or removed integrations should be validated against explicit repository, schema, or deployment evidence.—

These are workflow examples, not claims about current production changes.

Change Types

ADDED

A previously absent dependency edge or integration is documented.

REMOVED

A previously documented relationship is no longer present or supported.

MODIFIED

Direction, type, scope, or configuration of a relationship changed.

RECLASSIFIED

Evidence changed the confidence or interpretation of an existing relationship.

Change Confidence

VERIFIED

Direct evidence establishes the before/after state.

SUPPORTED

Multiple evidence sources support the change.

PROPOSED

A possible change has been identified but not validated.

UNKNOWN

Available evidence is insufficient to establish what changed.

Before / After Review

BEFORE Preserve the prior dependency edge, configuration reference, and evidence.

CHANGE Identify the exact event, commit, deployment, schema change, or documented action associated with the difference.

AFTER Record the resulting state and its verification source.

IMPACT Assess affected surfaces separately; do not infer impact solely from the existence of a dependency change.

Change Record Contract

Recommended fields: change_id, source_service_key, target_service_key, change_type, previous_edge, new_edge, evidence_ids, change_source, occurred_at, detected_at, confidence_state, impact_assessment, reviewed_by, reviewed_at, created_at, metadata.

Critical Guardrail

CHANGE ≠ INCIDENT
A dependency or configuration change does not automatically mean a service failed or that the change caused an incident. V207 keeps change detection, evidence, impact assessment, and root-cause analysis as separate review stages.

Safety & Platform State

V207 is a tracking and analysis surface. It does not modify dependencies, deploy code, trigger recovery, send notifications, delete records, or expose service-role credentials. No new Edge Function is deployed; the current project function-capacity limit remains respected.
