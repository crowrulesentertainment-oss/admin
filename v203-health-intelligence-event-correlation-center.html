Correlation Keys

Incident ID

Strong link when an event explicitly references the same incident.

Service Key

Connect events belonging to the same registered service.

Source ID

Preserve the originating record identity for traceability.

Time Window

Bound temporal relationships with explicit start and end times.

Confidence States

DIRECT

An explicit identifier establishes the relationship.

SUPPORTED

Multiple independent fields support the relationship.

CONTEXTUAL

Timing or shared service context suggests relevance but does not prove causation.

UNKNOWN

Evidence is insufficient; retain the events separately.

Investigation Views

INCIDENT TIMELINE Trace one incident across health, recovery, notifications, intelligence, and audit.

SERVICE TIMELINE Follow a service across bounded time windows.

SIGNAL TRACE Inspect the evidence behind an intelligence signal.

DELIVERY TRACE Connect notification routing, queue, attempts, and outcomes.

CROSS-SYSTEM Compare related events without assuming causation.

Correlation Record Contract

Recommended fields: correlation_id, event_a_id, event_b_id, relationship_type, service_key, incident_id, time_window_start, time_window_end, confidence_state, evidence, created_at, metadata.

Evidence first: every relationship should be explainable from recorded identifiers, timestamps, or explicitly documented context.

Safety State

CORRELATION • NOT CAUSATION
V203 provides structured event correlation for human investigation. It does not infer hidden causes, create unsupported incident relationships, trigger recovery, send notifications, change policies, or expose service-role credentials. No new Edge Function is deployed.
