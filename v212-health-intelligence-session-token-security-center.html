Session States

ACTIVE

A session is within its documented lifetime and has valid authorization context.

EXPIRING

A session is approaching an expected expiration boundary.

EXPIRED

The documented session lifetime has ended.

REVOKED

The session or credential has been intentionally invalidated.

Evidence Confidence

VERIFIED

Direct authoritative evidence supports the session finding.

SUPPORTED

Multiple relevant sources support the finding.

PROPOSED

A possible session difference requires validation.

UNKNOWN

Evidence is insufficient for a reliable conclusion.

Token Trust Boundary

CLIENT Do not expose service-role credentials or privileged secrets in browser-delivered code.

TOKEN Treat access tokens as security-sensitive credentials and avoid unnecessary persistence or logging.

SERVER Protected operations should validate authenticated identity and authorization at a trusted server boundary.

REFRESH Refresh behavior should follow the authentication provider's documented lifecycle and approved application design.

LOGGING Audit metadata should minimize credential material; never record raw access or refresh tokens as ordinary diagnostic payloads.

Recommended fields: session_audit_id, session_domain, actor_reference, session_reference, event_type, expected_state, observed_state, configuration_reference, evidence_ids, detected_at, confidence_state, related_identity_audit_id, related_access_audit_id, related_incident_id, reviewed_by, reviewed_at, created_at, metadata.

Critical Guardrails

SESSION ANOMALY ≠ ACCOUNT COMPROMISE
Unexpected session behavior requires evidence and investigation. It does not by itself establish compromise, abuse, or malicious intent.
TOKEN TELEMETRY ≠ TOKEN COLLECTION
Operational auditing should record safe metadata about token-related events without collecting raw credentials or unnecessary authentication secrets.

Safety & Platform State

V212 is a review and governance surface. It does not revoke sessions, rotate tokens, change authentication settings, alter storage, modify permissions, or collect credentials. It does not trigger recovery, notifications, or deletion. No service-role credentials are exposed and no new Edge Function is deployed; the current project function-capacity limit remains respected.
