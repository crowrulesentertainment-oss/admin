Drift Categories

CONFIGURATION

A setting differs from the documented or approved baseline.

SCHEMA

Database structure, policy, index, or object state differs from the recorded baseline.

AUTHORIZATION

Access-control or RLS configuration differs from the expected state.

DEPLOYMENT

A deployed artifact or version differs from the tracked deployment state.

INTEGRATION

A documented external or internal connection differs from its baseline.

SCHEDULE

A scheduler, interval, retention, or automation setting differs from baseline.

POLICY

An operational policy or governance setting differs from the approved record.

UNKNOWN

A difference exists but its category cannot yet be established.

Drift States

NO DRIFT

Observed state matches the verified baseline.

DETECTED

A difference has been observed but not yet validated.

VALIDATED

Evidence confirms that the difference is real.

REVIEWED

A human has assessed the evidence and documented the interpretation.

Confidence States

VERIFIED

Direct authoritative evidence supports the baseline and observed state.

SUPPORTED

Multiple relevant sources support the drift finding.

PROPOSED

A possible mismatch needs validation.

UNKNOWN

Evidence is insufficient for a reliable conclusion.

Baseline Comparison

EXPECTED Preserve the exact documented value, policy, schema, deployment, or configuration reference.

OBSERVED Capture the independently observed state and timestamp.

DELTA Describe only the specific difference supported by evidence.

CONTEXT Link relevant changes, incidents, dependencies, and audit events without assuming causation.

REVIEW Record who reviewed the finding and what evidence was accepted or rejected.

Critical Guardrail

DRIFT ≠ FAILURE ≠ CAUSE
A configuration difference does not by itself establish a service failure, security issue, incident, or root cause. V208 separates observation from validation, impact analysis, and causal investigation.

Safety & Platform State

V208 is a read-oriented analysis and governance surface. It does not automatically change configuration, remediate drift, deploy code, alter RLS, trigger recovery, send notifications, delete records, or expose service-role credentials. No new Edge Function is deployed; the current project function-capacity limit remains respected.
